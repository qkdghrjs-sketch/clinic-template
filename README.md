# 병원 홈페이지 템플릿 (clinic-template)

내과 의원용 홈페이지 템플릿입니다. **이 폴더 자체는 원본 템플릿이라 특정 병원 정보를 넣지 않습니다.**
새 병원을 만들 때는 이 폴더를 통째로 복사한 뒤, 복사본에서 작업하세요.

---

## 0. 이 템플릿에 들어 있는 것

- 메인 페이지 (첫 화면 슬라이드 3장, 진료센터 카드, 장비 소개, WHY 4가지, 의료진, 둘러보기)
- 의료진 소개 / 진료시간 / 오시는 길 / 둘러보기 / 비급여 안내 페이지
- 진료 세부 페이지 21개 (건강검진 4 · 내시경 4 · 내과진료 3 · 만성질환 3 · 특수클리닉 6 · 예방접종 1)
- 상단 메뉴, 하단 푸터, 전화·지도 플로팅 버튼, 카카오맵

지금 상태는 병원 이름이 `○○내과의원`, 전화번호가 비어 있는 **플레이스홀더 상태**입니다.
그대로 실행하면 화면은 정상적으로 뜨지만 내용은 비어 있는 예시로 보입니다.

---

## 1. 새 병원 만들기 — 전체 순서

### 1단계. 폴더 복사

`clinic-template` 폴더를 복사해서 이름을 병원에 맞게 바꿉니다. (예: `mirae-clinic`)

복사한 폴더에서 **아래 두 개는 지우세요.** 원본 병원의 배포·계정 정보가 딸려오는 것을 막기 위해서입니다.

- `.vercel` 폴더 (지우지 않으면 새 병원 사이트가 엉뚱한 프로젝트로 배포됩니다)
- `.env.local` 파일 (Vercel 접속 토큰이 들어 있습니다)

### 2단계. 실행해 보기

복사한 폴더에서 터미널을 열고:

```bash
corepack pnpm@11.10.0 install --node-linker=hoisted --package-import-method=copy
corepack pnpm@11.10.0 dev
```

브라우저에서 `http://localhost:3000` 을 엽니다.
Windows에서 설치 중 `EBUSY` 오류가 나면 `WINDOWS_RESET_AND_RUN.bat`을 더블클릭하세요.

### 3단계. 병원 정보 입력 — `src/lib/clinic.ts`

**병원 정보는 이 파일 한 곳에만 입력합니다.** 여기만 고치면 사이트 전체에 반영됩니다.
파일 안에서 `○○` 로 표시된 부분을 전부 실제 값으로 바꾸세요.

| 항목 | 설명 |
| --- | --- |
| `name` / `shortName` | 의원명 (예: `미래내과의원`) |
| `englishName` | 영문 표기 (안 쓰면 그대로 둬도 됩니다) |
| `slogan` | 한 줄 소개 |
| `concept` | 메인 하단 배너 문구 3가지 |
| `intro` | **모든 세부페이지 상단**에 나오는 소개 + 선택 이유 3가지 |
| `address` / `addressShort` | 주소 |
| `phone` / `phoneLabel` | 대표전화. **비워두면 "전화번호 준비 중"으로 표시됩니다** |
| `reservationUrl` | 네이버 예약 등 예약 링크. 비워두면 전화 연결로 동작합니다 |
| `naverMapUrl` / `kakaoMapUrl` / `tmapUrl` | 지도 앱 링크. 검색어 부분을 실제 주소로 바꾸세요 |
| `logoPrimary` / `logoSecondary` | 로고 이미지 주소. **비워두면 병원 이름 글자가 대신 나옵니다** |
| `representative` / `businessNumber` | 대표자명 / 사업자등록번호 |
| `hours` / `hoursNotice` | 진료시간 표와 안내 문구 |
| `parkingNotice` / `facilityNotice` | 주차·시설 안내 |
| `doctors` | 의료진. 원장님이 여러 분이면 같은 모양으로 배열에 추가하세요 |
| `navItems` | 상단 메뉴 구조 |
| `suppliedImages` / `tourImages` | 병원 사진 |

> ⚠️ **원장 성함·약력·자격·진료시간은 병원에서 확인받은 내용만 입력하세요. 추측해서 채우면 안 됩니다.**

### 4단계. 진료 페이지 문구 검토 — `src/lib/servicePages.ts`

이 파일에 진료 세부 페이지 21개의 문구가 전부 들어 있습니다.
파일 안에서 **`// [병원별 수정 필요]`** 주석을 찾아 그 아래 줄을 고치세요.
주석이 없는 문구는 일반적인 내과 설명이라 그대로 써도 됩니다.

- 그 병원이 **하지 않는 진료**는 해당 항목을 통째로 지웁니다.
  (지운 뒤에는 `clinic.ts`의 `navItems`에서 그 메뉴 링크도 같이 지워야 합니다. 안 지우면 빈 페이지가 뜹니다.)
- 진료를 **추가**하려면 `servicePages.ts`에 항목 하나를 복사해 붙여넣고 `navItems`에 링크를 추가합니다.
  새 파일을 만들 필요는 없습니다.

### 5단계. 이미지 교체

`src/lib/clinic.ts` 안의 두 곳입니다.

- `suppliedImages` — 메인 카드·배경에 돌려쓰는 사진 12장
- `tourImages` — 둘러보기 사진 11장 (`title`은 메인 미리보기에서 이름으로 찾아 쓰이니 되도록 그대로 두세요)

지금 들어 있는 주소는 **미리보기용 임시 사진**입니다. 실제 병원 사진으로 반드시 교체하세요.
직접 찍은 사진을 쓰려면 `public/` 폴더에 넣고 `/사진이름.jpg` 형태로 적으면 됩니다.
외부 주소를 쓰는 경우 `next.config.ts`의 `remotePatterns`에 그 도메인을 추가해야 화면에 나옵니다.

### 6단계. 지도 교체 — `public/kakaomap.html`

카카오맵(map.kakao.com)에서 병원을 검색 → **지도 퍼가기** → 나온 코드의 `timestamp`, `key`, 컨테이너 id 값을
`public/kakaomap.html`에 덮어씁니다. React 코드는 건드리지 않습니다.

### 7단계. 확인

```bash
corepack pnpm@11.10.0 build   # 빌드 통과 확인
corepack pnpm@11.10.0 lint    # 문법 검사
npx tsc --noEmit              # 타입 검사
```

셋 다 통과하면 `corepack pnpm@11.10.0 dev`로 실행해서 **모바일 화면 기준으로** 각 페이지를 확인합니다.
(브라우저에서 F12 → 휴대폰 모양 아이콘)

체크리스트:

- [ ] 병원 이름·주소·전화번호가 모든 페이지에 맞게 나오는가
- [ ] 진료시간이 맞는가
- [ ] 상단 메뉴의 모든 링크가 실제로 열리는가
- [ ] 사진이 전부 실제 병원 사진으로 바뀌었는가
- [ ] 지도가 실제 병원 위치를 가리키는가
- [ ] 의료진 약력이 병원에서 확인받은 내용인가
- [ ] `○○` 가 화면 어디에도 남아 있지 않은가
- [ ] 모바일 화면에서 글자가 잘리거나 겹치지 않는가

### 8단계. 배포 (Vercel)

1. 복사한 폴더를 새 GitHub 저장소에 올립니다.
2. Vercel에서 **New Project** → 그 저장소 선택
3. Framework Preset이 **Next.js** 인지 확인 → **Deploy**
4. 도메인이 있으면 Project Settings → Domains에서 연결

## 2. 꼭 지킬 것

- **병원 정보는 `clinic.ts`에만 입력합니다.** 컴포넌트 파일에 직접 병원 이름이나 전화번호를 적지 마세요.
- **의료광고법 주의** — 최상급 표현(최고·유일·1등), 치료효과 보장, 환자 체험담 강조는 쓰지 않습니다.
- **모바일 화면 기준으로 확인**합니다. 병원 홈페이지 방문자는 대부분 휴대폰으로 봅니다.
- 이 원본 템플릿 폴더에는 특정 병원 정보를 저장하지 않습니다.

## 3. 검색 노출 — AI 검색(GEO) + 네이버 SEO

설정은 **`src/lib/seo.ts` 한 파일**에 모여 있습니다.

### 가장 중요한 한 줄 — 템플릿 모드 스위치

```ts
export const IS_TEMPLATE = true;   // 판매용 데모: 검색에 안 잡힘 (기본값)
                                   // 실제 병원 사이트를 만들면 false 로!
```

`false` 로 바꾸면 `robots.txt`·메타 robots·sitemap 이 **한꺼번에** 노출 모드로 바뀝니다.
`layout.tsx` 를 직접 고칠 필요가 없습니다.
템플릿이 "○○내과의원" 이름으로 검색에 뜨면 안 되므로 기본값이 `true` 입니다.

### 채워야 할 값

| 값 | 설명 |
|---|---|
| `SITE_URL` | 배포 후 실제 주소. sitemap과 구조화 데이터가 이 값을 씁니다 |
| `TARGET_REGIONS` | 네이버 "지역명 + 질환명"을 노릴 동네 목록 |
| `LOCAL_TOPICS` | 지역 페이지로 만들 주제 (기존 진료 슬러그를 그대로 재사용) |
| `NAVER_SITE_VERIFICATION` | 네이버 서치어드바이저 인증 코드 |
| `GOOGLE_SITE_VERIFICATION` | 구글 서치콘솔 인증 코드 |

### 자동으로 되는 것

| 경로 | 내용 |
|---|---|
| `/llms.txt` | AI가 읽는 병원 요약. 진료시간·주소·진료항목을 평문으로 못 박습니다 |
| `application/ld+json` | `MedicalClinic` · `Physician` · `FAQPage` 구조화 데이터 (layout에 자동 삽입) |
| `/robots.txt` | 네이버(Yeti)·다음·GPTBot·ClaudeBot·PerplexityBot 허용 |
| `/sitemap.xml` | 전체 페이지 자동 수집 |
| `/local/[지역]/[질환]` | 지역 × 주제 조합 페이지 자동 생성 |

**지역 페이지 개수 = `TARGET_REGIONS` × `LOCAL_TOPICS`.** 기본값 3 × 8 = 24페이지.

경로에 `/local/` 이 붙는 이유: 루트에 이미 `[...slug]` 가 있고 기존 진료 페이지
21개 중 19개가 `/chronic/hypertension` 같은 2단 경로라서, `/[지역]/[질환]` 을
그대로 만들면 **기존 진료 페이지를 전부 가로챕니다.**

## 4. 배포 전 검수 — 의료광고 심의

```
pnpm check
```

| 검사 항목 | 예시 |
|---|---|
| 최상급 표현 | 최고, 최우수, 1등 |
| 유일·독점 | 유일한, 독보적 |
| 치료효과 보장 | 완치됩니다, 부작용 없음, 100% |
| 비교광고 | **대학병원급**, 타 병원보다 |
| 환자 체험담 | 치료 후기, 만족도 00% |
| 환자 유인 | 무료 시술, 선착순, 특가 |
| 미기재 자리표시 | `○○` 가 남아 있는 곳 |

**위반이 하나라도 있으면 실패(exit 1)로 끝납니다.**

> `대학병원급` 은 실수하기 쉽습니다. 장비가 좋다는 뜻으로 쓰지만
> 다른 의료기관과의 비교라서 심의에서 자주 반려됩니다.
> "고해상도 내시경 장비 보유" 처럼 사실만 적으면 됩니다.

## 5. 기술 정보 (참고)

- Next.js 16 (App Router) + React 19 + Tailwind CSS v4
- 색상 토큰(`navy-*`, `sky-*`, `gold-*`)은 `src/app/globals.css` 상단에 정의되어 있습니다. `tailwind.config` 파일은 없습니다.
- 진료 세부 페이지는 `src/app/[...slug]/page.tsx` 하나가 전부 그려냅니다.
- 테스트 코드는 없습니다. 확인 = `build` + `lint` + `tsc --noEmit` + 실제 화면 확인.
- Windows에서 pnpm symlink 오류를 피하려고 `pnpm-workspace.yaml`에 `nodeLinker: hoisted`,
  `packageImportMethod: copy`가 고정돼 있습니다. 바꾸지 마세요.
